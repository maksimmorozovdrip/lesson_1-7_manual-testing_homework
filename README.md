# ДЗ 1-7. Утро после атаки

Ночью сайт веб-мастерской подвергся хакерской атаке. Найдите и исправьте ошибки, подтвердите результат проверками. В бонусе добавьте ловушки и временные ограничения.

**База: 5 баллов. Бонус: 5 баллов.** Ориентир: около 3 часов на базу и ещё 2 на бонус. [Переписка дежурного](INCIDENT_CHAT.md) добавляет контекст, читать её необязательно.

## Запуск

Откройте `index.html` через Live Server или другой статический сервер, не через `file://`. npm-пакеты не нужны.

Данные остаются в этом браузере и на этом адресе; после публикации локальные заявки не перенесутся. В «Условиях проверки» есть задержка, ошибка и сброс к трём исходным заявкам. После перезагрузки режим обычный. Перед независимой проверкой сбросьте стенд, сохранив нужные свидетельства.

| Файл | Назначение |
| --- | --- |
| `index.html`, `src/styles.css` | Интерфейс и оформление |
| `src/app.js` | Поведение приложения |
| `src/api.js` | Готовый сервис внутри браузера, менять его не требуется |
| `src/security.js` | Заготовки для бонусов |
| [TESTING.md](TESTING.md) | Единственный файл отчёта |

`src/api.js` работает внутри браузера: POST в Network не будет. Проверяйте интерфейс и сохранённые данные.

## База: найти и исправить восемь багов

Используйте маршрут из практики 1-7: требование, проверка, баг-репорт, исправление, повторная и регрессионная проверка. Для исправлений достаточно HTML/CSS, DOM, форм и обработки ошибок из предыдущих занятий.

В реализации есть по одному дефекту на каждый пункт ниже. Недостающие бонусы не входят в эти восемь.

| ID | Ожидаемое поведение | Баллы |
| --- | --- | ---: |
| R1 | Имя после удаления крайних пробелов содержит от 2 до 60 символов. Направление выбрано из списка; комментарий необязателен, до 200 символов. Некорректная форма не создаёт заявку | 0,5 |
| R2 | Фильтр показывает только выбранное направление. Счётчик равен числу видимых карточек, в том числе нулю | 0,5 |
| R3 | Любая часть карточки выбирает одну и ту же заявку. Её данные появляются в подробностях. Карточки доступны через Tab и выбираются через Enter | 0,5 |
| R4 | «Сбросить интерфейс» очищает форму, снимает выбор карточки и возвращает фильтр «Все направления». Заявки остаются | 0,5 |
| R5 | На ширине 360 px форму и основную кнопку можно использовать без горизонтальной прокрутки | 0,5 |
| R6 | Во время отправки повторное действие не создаёт дубли. После завершения можно отправить следующую заявку | 0,5 |
| R7 | Комментарий отображается как обычный текст в карточке, подробностях и после перезагрузки. Введённые символы сохраняются | 1 |
| R8 | Успех показывается только после сохранения. При отказе нет новой заявки, введённые значения остаются и повтор доступен. При успехе форма очищается | 1 |

Сначала воспроизведите дефект, затем исправляйте код. В `TESTING.md` заполните чек-лист и восемь баг-репортов по шаблону. После каждого исправления повторите исходные шаги и проверьте соседний сценарий. Эти шаги служат тест-кейсом, отдельный документ не нужен.

В каждом пункте: 40% за отчёт, 40% за исправление причины, 20% за повторную и соседнюю проверку. Несколько симптомов одной причины считаются одним багом. Частичный результат оценивается по этой же схеме.

Для проверки текста достаточно простой HTML-разметки без скриптов. Используйте вымышленные данные. Не меняйте требования под текущее поведение приложения.

## Бонус: ловушки и реакция на инциденты

Бонусы можно выполнять частично. Они не должны ломать исправленную базу.

### Шесть ловушек, по 0,5 балла

| ID | Когда регистрировать инцидент |
| --- | --- |
| T1 | Шестая попытка обновить список за последние 5 секунд. Одна-две попытки или клики с большими интервалами не вызывают сигнал |
| T2 | При отправке заполнено скрытое поле `supportCode`. Обычная форма и автозаполнение реальных полей его не заполняют |
| T3 | Вызвана скрытая кнопка `staff-export`. Никакой настоящей выгрузки она не делает |
| T4 | При отправке получено направление, отличное от `html`, `javascript`, `api`. Пустой выбор считается обычной ошибкой ввода, не инцидентом |
| T5 | При загрузке в ключе `workshop-hw7:canary` обнаружено `role: "admin"` вместо `"visitor"`. Для проверки измените запись через DevTools и перезагрузите страницу. Отсутствие записи или повреждённый JSON не считаются атакой |
| T6 | При загрузке в адресе есть параметр `staff=1`. Другие параметры и значения не вызывают сигнал |

Заготовки в `src/security.js`: `checkActivity` получает `startup`, `refresh`, `submit`, `decoy`; у `submit` есть `details.topic` и `details.supportCode`. `reportIncident(type, reason)` пока выводит событие на страницу. Условия ловушек пишете вы.

За ловушку: 0,25 за срабатывание, 0,25 за обычную/пограничную проверку без ложного сигнала. Обе запишите в отчёте. Подмены делайте через DevTools в своей копии. Открытие консоли, копирование текста и клавиатура не должны вызывать ограничения.

### Журнал и временные ограничения, 1,5 балла

- **0,5:** общий журнал в localStorage: время, тип и причина, последние 30 событий. Журнал виден и восстанавливается после перезагрузки. Пустые или повреждённые данные не ломают приложение.
- **0,5:** после инцидента на 30 секунд недоступны отправка и обновление списка. Видны причина и таймер; чтение остаётся доступным. По окончании функции восстанавливаются. Проверяйте ограничение в обработчиках через `isRestricted()`, а не только оформлением кнопки.
- **0,5:** сохранённое время окончания `blockedUntil` позволяет продолжить отсчёт после перезагрузки. Новые попытки во время паузы не продлевают её. Один неизменившийся сигнал при загрузке не должен каждый раз запускать новую паузу: обработайте его однократно. Можно убрать обработанный параметр URL и восстановить маркер `visitor`. Учебный сброс снимает ограничения и очищает журнал; в него нужно добавить очистку таймера и состояния ваших бонусов.

Для отдельной проверки журнала и ограничений есть «Пробный инцидент»: ловушки для этого делать необязательно. Достаточно одной вкладки; синхронизация вкладок не требуется. Ключи storage начинайте с `workshop-hw7:`, содержимое форм в журнал не записывайте. Маркер не даёт прав администратора. localStorage можно изменить; это учебная модель, не защита от DDoS.

### GitHub Pages, 0,5 балла

Настройте публикацию **самостоятельно**. Публикуйте проект целиком с корневым `index.html` и папкой `src`, а не только `src`. Сайт должен работать по адресу вида `https://login.github.io/repository/` без локального сервера. Проверьте обычный сценарий и выполненные бонусы; опубликованный код должен совпадать со сдаваемым. Готового workflow нет. Файл `.nojekyll` сохраняет файлы без обработки Jekyll, но не настраивает Pages.

DOM, события, формы, JSON и localStorage уже были в модуле; Pages встречался в прошлых ДЗ. В бонусе самостоятельно разберите интервалы времени, параметры URL, приманки и защиту от повторной регистрации. Поисковые запросы:

| Для чего | Поисковый запрос |
| --- | --- |
| Интервал действий и отсчёт | `JavaScript Date.now setInterval clearInterval sliding window` |
| Параметры адреса и однократная обработка | `URLSearchParams history.replaceState remove query parameter` |
| Сохранение журнала | `localStorage JSON.parse try catch Array.isArray array slice` |
| Приманки и проверка подмен | `honeypot field autocomplete accessibility`, `Chrome DevTools edit DOM localStorage` |
| Работа с готовыми модулями | `JavaScript import export ES modules relative path` |
| Публикация | `GitHub Pages publishing source branch relative paths` |
